# kronos-py / frontend

投資初心者を対象とした **日本株アプリ（React + Vite）** の UI/UX 方針です。過去の**確定**データと Kronos による**予測**を誤認させないことを最優先にします。

## プロジェクト構成と開発サーバ（フェーズ0）

本ディレクトリには Vite + React（TypeScript）のソースがあります。

| 項目 | 内容 |
|------|------|
| 開発サーバ | `npm run dev`（既定ポート **5173**） |
| API プロキシ | [`vite.config.ts`](./vite.config.ts) で `/api` → `http://127.0.0.1:8000`。ブラウザからは相対パス `/api/health` でバックエンドに届く |
| フェーズ0の画面 | [`src/App.tsx`](./src/App.tsx) が `GET /api/health` を表示（読み込み中は Skeleton） |

先に [backend の README](../backend/README.md) に従い **API を起動**してからフロントを開いてください。バックエンドが無い場合は接続エラーとヒントが表示されます。

依存関係は [package.json](./package.json) に記載しています。**お使いのパッケージマネージャで依存を解決したうえで** `npm run dev` を実行してください（チーム方針でコマンドが異なる場合はそれに従う）。

## 1. 視覚的設計（過去と未来を誤認させないビジュアル）

- **タイムラインの分断（境界線の明示）**  
  - 過去（確定）と Kronos（予測）の境界に、太めの垂直点線（バーティカルライン）を配置する。  
  - 境界付近に「ここからAI予測」などのラベルを表示し、未来の数値を事実と誤解するリスクを下げる。
- **予測データのスタイル差別化**  
  - 過去のローソク足は不透明（100%）で描画する。  
  - 予測ローソク足は半透明（例: 不透明度 50%）、または塗りつぶさず枠線とヒゲのみで、不確実性を示す。
- **ブレ幅（不確実性）の可視化（任意・バックエンド対応後）**  
  - 予測エリアに信頼区間などが返せるようになった場合、薄い背景の帯（シェード）で変動し得る範囲を示す。v1 で API が未対応なら非表示または後続フェーズとする。

## 2. 画面レイアウト設計（2カラム・グリッド構造）

右サイドは **Kronos の予測の注意事項・根拠テンプレ**（例: 過去〇本の履歴に基づく推定）や API メタ情報用に使い、**生成 AI による市況ニュースは扱わない**。

- **上部：インフォメーションヘッダー**  
  - 銘柄名、コード、現在値、前日比、日本語での「始値・高値・安値・終値」を横並び。  
  - 予測表示の ON/OFF トグル。
- **左側（メイン・約 3/4 幅）：ハイブリッドチャート**  
  - 上段：ローソク足（確定＋予測）。  
  - 下段：出来高（**確定のみ**）。予測足の出来高は誤解を招きやすいため v1 では出さないか、出す場合は注記を付ける。  
  - チャート下に期間切り替え（例:「1ヶ月」「3ヶ月」「1年」）— API の `period` と対応させ、日足中心が初心者向けに安定しやすい。
- **右側（サイドバー・約 1/4 幅）**  
  - Kronos の注意書き、利用モデル、`lookback` / `pred_len` など API から返るメタを表示する。

## 3. インタラクション設計（初心者を迷わせない操作）

- **ツールチップ**  
  - 過去：通常の株価表示。  
  - 予測：「Kronos による予測値」と明記し、注意書きを添える。
- **スクロールとチャート操作**  
  - チャート領域を一度クリックしてフォーカスした後のみ、ズーム・パンを有効にし、ページ全体のスクロールと競合しにくくする。
- **投資予算の概算（日本株）**  
  - チャート付近に「100 株（単元）で約〇〇円」などの**参考**表示。予測値ベースのときは「予測に基づく試算」と区別する。**投資助言ではない**旨を一文入れる。

## 4. フロントエンド実装方針（React + Vite）

- **非同期 UX**  
  - 取得中は白画面やスピナーのみにせず、チャート用の **Skeleton（骨組みプレースホルダ）** を表示する。
- **パフォーマンス**  
  - ヘッダー数値・ツールチップの更新でチャート全体が再マウントされないよう、コンポーネント分割や `React.memo`、必要なら Zustand 等で更新範囲を限定する。

## 実装フェーズ

リポジトリ全体の「目指す体験」は [../README.md](../README.md) と対応させる。

### フェーズ 0（土台）

- [x] Vite + React（TS）、開発プロキシ `/api` → `127.0.0.1:8000`。
- [x] トップ画面で **`GET /api/health`** の結果を表示（読み込み中は Skeleton）。
- **関連 UX:** 「バックエンドに届く」ことがヘルス表示で分かる。

### フェーズ 1（v1 コア）

- **レイアウト:** 上ヘッダー、左メイン（チャート）・右サイド（注意・メタ）の 2 カラム骨格。
- **状態:** 「未ロード / ロード中 / ロード済」「市場データなし / あり」「予測なし / あり」を画面で判別可能にする。
- **フロー:** モデル読込 → 銘柄・期間でデータ取得 → チャート描画 → 予測実行 → 確定＋予測の重ね描き（境界線・スタイル差）。
- **フォーム:** `lookback`・`pred_len`・トグル；サーバーの `max_context` と矛盾する入力は無効化またはエラー表示。
- **非同期:** 取得・予測中は **Skeleton**、主要操作はスピナーのみにしない。
- **関連 UX:** [../README.md](../README.md) の「目指す体験（UX の芯）」の 1〜4 を満たす最小製品。

### フェーズ 2（v1 磨き）

- ツールチップの過去／予測の文言差、チャート領域フォーカス後のみズーム。
- 100 株概算・投資助言ではない旨の注記。
- `React.memo` / 状態管理でヘッダー・ツールチップ更新時にチャートが巻き添え再描画されないよう整理。
- アクセシビリティ（色以外の区別）を必要に応じて追加。

### フェーズ 3（v2）

- ファインチューニング用の画面・ナビは **メインの初心者フローから分離**（設定・詳細など）する想定。詳細は backend README。

### フェーズ別と UX の対応（一覧）

| UX の芯（抜粋） | 主に該当フェーズ |
|-----------------|------------------|
| モデル読込後だけ予測 | 1 |
| 銘柄・期間・エラーが分かる | 1 → 2 で文言磨き |
| lookback / max_context | 1（入力制約） |
| 確定と予測の視覚分離 | 1 → 2 |
